### What happens

In Label Studio the settings module that the project's code names star-imports a base module, and the import goes through a source-root alias. MintMap does not resolve that star import. The base module's `INSTALLED_APPS`, `MIDDLEWARE`, `AUTHENTICATION_BACKENDS` and `REST_FRAMEWORK` are never read, and the scan reports only the unresolved import (`settings_star_import_unresolved`) and `missing_setting` gaps, not which settings the unread base module holds.

### Minimal project

This reproduces it (the same shape as Label Studio, whose `server.py` names the settings module through the package path):

```python
# shop/manage.py
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "core.settings.shop")

# shop/server.py
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "shop.core.settings.shop")

# shop/__init__.py, shop/core/__init__.py, shop/core/settings/__init__.py: empty

# shop/core/settings/base.py
INSTALLED_APPS = ["django.contrib.auth", "django.contrib.sessions", "rest_framework"]
MIDDLEWARE = ["django.contrib.sessions.middleware.SessionMiddleware"]
ROOT_URLCONF = "core.urls"

# shop/core/settings/shop.py   ("shop/" is a source root, so this module is importable as core.settings.shop)
from core.settings.base import *  # noqa

SESSION_COOKIE_AGE = 60 * 60

# shop/core/urls.py
urlpatterns = []
```

`mintmap scan .` (checked on 0.6.0a2, whose analysis is that of 0.6.0a1):

```
files parsed 8/8  parse failures 0  settings ['shop.core.settings.shop']  root URLconf ['shop.core.urls']
  settings  authentication settings, one lock entry per group: settings:AUTHENTICATION_BACKENDS, settings:AUTH_CORE
gaps by type: {'missing_setting': 2, 'root_urlconf_inferred': 1, 'settings_module_missing': 1, 'settings_star_import_unresolved': 1}
  gap missing_setting: shop/core/settings/shop.py MIDDLEWARE :: not assigned
  gap missing_setting: shop/core/settings/shop.py ROOT_URLCONF :: not assigned
  gap root_urlconf_inferred: - ROOT_URLCONF :: shop.core.urls
  gap settings_module_missing: - DJANGO_SETTINGS_MODULE :: core.settings.shop
  gap settings_star_import_unresolved: shop/core/settings/shop.py shop.core.settings.shop :: from core.settings.base import *
```

There is no `settings:MIDDLEWARE` or `settings:INSTALLED_APPS(auth)` group, although `base.py` sets both.

Likely cause: the `from ... import *` branch of the settings evaluator (`src/mintmap/core/settings_extract.py`, around line 710) looks up the star-import source in `self.p.modules` as written, without `Project.unalias` (`src/mintmap/core/project.py`), which the project model uses for star imports elsewhere.

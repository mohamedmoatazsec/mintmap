### What happens

django-auth-ldap is not in the catalog, so MintMap knows nothing about its settings. In the round-4 mutation test on Tandoor, two LDAP settings changes that the evaluation counts as harmful passed `mintmap diff` with exit 0. The first, `AUTH_LDAP_GLOBAL_OPTIONS = {ldap.OPT_X_TLS_REQUIRE_CERT: ldap.OPT_X_TLS_NEVER}`, stops verifying the directory's certificate. The second, `AUTH_LDAP_PERMIT_EMPTY_PASSWORD = True`, was pre-registered as harmful, but Tandoor's login forms never pass an empty password, so it removes a defence in depth. MintMap does report the backend as a gap (`hook_target_not_in_catalog`), treats the password factor as `unknown_backend:...LDAPBackend`, and fingerprints a project receiver connected to `populate_user`.

### Minimal snippet

```python
# settings.py
AUTHENTICATION_BACKENDS = [
    "django_auth_ldap.backend.LDAPBackend",
    "django.contrib.auth.backends.ModelBackend",
]
AUTH_LDAP_SERVER_URI = "ldap://ldap.teahouse.example"
AUTH_LDAP_USER_DN_TEMPLATE = "uid=%(user)s,ou=people,dc=teahouse,dc=example"
```

```python
# members/signals.py
from django_auth_ldap.backend import populate_user


def mark_staff(sender, user, ldap_user, **kwargs):
    user.is_staff = "cn=baristas" in ldap_user.group_dns


populate_user.connect(mark_staff)
```

On a copy of `examples/demo` with this snippet, `mintmap scan` prints `authenticate() factor: password|unknown_backend:django_auth_ldap.backend.LDAPBackend` and `gap hook_target_not_in_catalog: - AUTHENTICATION_BACKENDS :: django_auth_ldap.backend.LDAPBackend`. Run `mintmap update` and `mintmap accept --all`, then add `AUTH_LDAP_GLOBAL_OPTIONS = {ldap.OPT_X_TLS_REQUIRE_CERT: ldap.OPT_X_TLS_NEVER}` to settings.py: `mintmap diff` prints `exit 0 (ok)` (checked on 0.6.0a2, whose analysis is that of 0.6.0a1). Changing `mark_staff` to `user.is_staff = True` does raise `fingerprint_changed` on `settings:AUTH_HOOKS(project code)`.

### Acceptance criteria

- [ ] Catalog entries for the backend's `authenticate` (as a check with the `password` factor), the hook settings and the signals the library calls project code through (`populate_user`, `ldap_error`).
- [ ] Every entry cites the library source file it was read from, with the release and a line number where the fact is line-specific. Read the source from an unpacked wheel; do not install or import it.
- [ ] The package and version are added to `package_versions` and `verified_package_versions`.
- [ ] The security-relevant `AUTH_LDAP_*` settings (at least PERMIT_EMPTY_PASSWORD, GLOBAL_OPTIONS, CONNECTION_OPTIONS, START_TLS, SERVER_URI, BIND_DN, USER_SEARCH / USER_DN_TEMPLATE, REQUIRE_GROUP, DENY_GROUP, USER_FLAGS_BY_GROUP; confirm against the library source) are in a settings group, so the change above raises `fingerprint_changed`.
- [ ] A test with a synthetic project.

See [Add a catalog entry](https://github.com/mohamedmoatazsec/mintmap/blob/main/CONTRIBUTING.md#add-a-catalog-entry) in CONTRIBUTING.md.

### What happens

Settings values that are arithmetic on constants are fingerprinted as expressions, not as values. Rewriting one without changing the result raises `fingerprint_changed`. In the evaluation this was `365*60*24*60` → `60*60*24*365`.

### Minimal snippet

In `examples/demo/teahouse/settings.py` change

```python
PASSWORD_RESET_TIMEOUT = 60 * 60
```

to

```python
PASSWORD_RESET_TIMEOUT = 3600
```

`mintmap diff examples/demo` on 0.6.0a2, whose analysis is that of 0.6.0a1:

```
FINGERPRINT_CHANGED    settings:package:django settings group settings:package:django changed: PASSWORD_RESET_TIMEOUT: <dynamic 60 * 60> -> 3600; previous review (accepted) no longer applies
exit 4 (fingerprint_changed)
```

### Acceptance criteria

- [ ] Arithmetic on int and float literals (`+ - * / // %`, unary minus, parentheses, and `**` with an int exponent from 0 to 64) is folded to its value before the settings group is fingerprinted. If any intermediate int result is 2**64 or larger in absolute value, or any operation raises (ZeroDivisionError, OverflowError), the expression keeps today's `<dynamic ...>` text. Nothing else is evaluated: no names, no calls, no attribute access. The input is pull-request code: `10 ** 10 ** 10` must stay dynamic and the scan must finish at once.
- [ ] Both rewrites above exit 0, and `60 * 60` → `60 * 61` still raises `fingerprint_changed`; `10 ** 10 ** 10` stays `<dynamic ...>`.
- [ ] Refresh the demo baseline with Python 3.13, as examples/demo/README.md describes: `python3.13 -I scripts/run_mintmap.py update examples/demo`, `python3.13 -I scripts/run_mintmap.py accept examples/demo --group settings --reviewer <you>`, then `python3.13 scripts/render_demo.py` to re-render the README image (CI runs it with `--check`). The demo's `PASSWORD_RESET_TIMEOUT = 60 * 60` changes fingerprint, the `demo` CI job expects `mintmap diff examples/demo` to exit 0, and a lock written with another Python version adds an INFO line that fails the image check.
- [ ] Existing locks: say in the changelog whether settings groups with such expressions need `mintmap update` once.
- [ ] Tests.

This is a small, well-bounded change (`src/mintmap/core/settings_extract.py`), which is why it is marked as a good first issue. It does change fingerprints, so it ships with the next evaluated release.

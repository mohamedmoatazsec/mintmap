> The demo project and documents named below arrive with #12 and are not on `main` yet.

### What happens

`mintmap scan` prints the coverage header, the review queue, the details of every path and the gaps. For a quick look, or for a pull-request comment, the review queue alone is enough. The demo script currently filters the output with `grep`.

### Example

```
$ mintmap scan examples/demo --queue-only
REVIEW QUEUE: 12 lock entries: 5 path(s) in 2 credential kind(s), ...
  kind:session  full login sessions (...): 4 path(s) from 3 entry point(s); 0 high, 3 medium, 1 low
    ...
```

### Where

`summarize()` and `review_queue()` in `src/mintmap/cli.py`. Report formatting only: no change to the analysis, the JSON report or the lock.

### Acceptance criteria

- [ ] `mintmap scan <dir> --queue-only` prints the lines `review_queue()` returns and nothing else.
- [ ] Without the option the output is unchanged.
- [ ] The option is in `--help` and in the README command table.
- [ ] `scripts/demo.sh` and `docs/assets/demo.svg` stay unchanged (the maintainer decides separately whether the demo should use the option: the demo's review queue is 22 lines, up to 222 characters wide, against the 6 lines the README image shows now).
- [ ] A test in `tests/test_cli.py`.

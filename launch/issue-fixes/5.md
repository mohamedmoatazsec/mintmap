### What happens

A DRF `ModelSerializer` whose model is a credential model creates the credential in `super().create()`. MintMap reports no path for the view that uses it.

### Minimal snippet

Add to `examples/demo/members/views.py` and route it:

```python
from rest_framework import generics, serializers


class DeviceKeySerializer(serializers.ModelSerializer):
    class Meta:
        model = Token
        fields = ["key"]

    def create(self, validated_data):
        validated_data["user"] = self.context["request"].user
        return super().create(validated_data)


class DeviceKeyView(generics.CreateAPIView):
    serializer_class = DeviceKeySerializer
```

```python
path("api/device-key/", views.DeviceKeyView.as_view()),
```

`mintmap diff examples/demo` prints `exit 0 (ok)` (checked on 0.6.0a2, whose analysis is that of 0.6.0a1).

### Acceptance criteria

- [ ] A `ModelSerializer` whose `Meta.model` is a catalogued credential model (or a project model MintMap already treats as a credential) is a mint site when a create view or viewset uses it.
- [ ] The snippet makes `mintmap diff` exit with `new_path`.
- [ ] The related case from the evaluation, an update serializer that writes a credential field from request data, is covered or split into its own issue.

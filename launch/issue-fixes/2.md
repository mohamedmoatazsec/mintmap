### What happens

MintMap links an admin registration to a mint only when the model's `save()` is a catalogued mint. A project model that holds a credential and is editable in the admin is not reported, so an administrator typing or changing an API key is not on the map.

### Minimal snippet

```python
# members/models.py
class ApiKey(models.Model):
    owner = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    key = models.CharField(max_length=40, unique=True)
```

```python
# members/admin.py
from django.contrib import admin

from .models import ApiKey


@admin.register(ApiKey)
class ApiKeyAdmin(admin.ModelAdmin):
    fields = ["owner", "key"]
```

With `django.contrib.admin` installed and `path("admin/", admin.site.urls)` routed, `mintmap scan` lists the admin's own login and password paths, but nothing mentions `ApiKey` or `ApiKeyAdmin` (checked on 0.6.0a2, whose analysis is that of 0.6.0a1).

### Acceptance criteria

- [ ] A `ModelAdmin` for a project model with a credential-named field (`key`, `token`, `secret`, ...) is reported, as a path or as a candidate with the reason.
- [ ] Admin actions and `save_model` overrides that write such a field are covered, or listed as a gap.
- [ ] Removing `key` from `fields` or adding it changes the entry's fingerprint.
- [ ] Tests with a synthetic project.

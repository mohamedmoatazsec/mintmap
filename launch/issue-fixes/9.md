> The demo project and documents named below arrive with #12 and are not on `main` yet.

### What happens

A same-module helper whose name, after leading underscores, starts with `check_` (also `verify`, `validate`, `confirm`, ...) is treated as an unrecognised check, so a harmless extract-method raises `fingerprint_changed` and an `unrecognized_check_call` gap. In the evaluation this was one of the 7 of 22 harmless changes that were flagged (`_check_token_limit` in CVAT; renamed to `_enforce_token_limit`, the false alarm went away). Separately, a helper that returns the result of a recognised check raises a finding whatever its name.

### Snippet 1: a helper named like a check

In `examples/demo/members/views.py`, `ApiTokenView.post`, replace `"Wrong username or password."` with `_check_detail()`, and add

```python
def _check_detail():
    return "Wrong username or password."
```

`mintmap diff examples/demo` (checked on 0.6.0a2, whose analysis is that of 0.6.0a1):

```
FINGERPRINT_CHANGED    363c72388024ca9c  evidence inputs changed (checks); previous review (accepted) no longer applies
COVERAGE_REGRESSION    363c72388024ca9c  path analysis became incomplete: unrecognized_check_call|members/views.py|members.views.ApiTokenView.post|members.views._check_detail (project function containing no check MintMap recognises)
COVERAGE_REGRESSION    -                 1 new analysis gap(s): unrecognized_check_call|members/views.py|members.views.ApiTokenView.post|members.views._check_detail (project function containing no check MintMap recognises)
exit 36 (fingerprint_changed, coverage_regression)
```

The same extraction named `_wrong_password_detail()` exits 0.

### Snippet 2: a helper that returns a recognised check

In `examples/demo/members/views.py`, replace

```python
if not default_token_generator.check_token(member, token):
    return HttpResponseForbidden()
```

with

```python
if not _check_reset_link(member, token):
    return HttpResponseForbidden()
```

and add

```python
def _check_reset_link(member, token):
    return default_token_generator.check_token(member, token)
```

`mintmap diff examples/demo`:

```
FINGERPRINT_CHANGED    1686eb3b06d009ce  evidence inputs changed (catalog, checks); previous review (accepted) no longer applies
FINGERPRINT_CHANGED    cd678fdb9fe16dfa  candidate members.views.finish_reset -> password_set[set_password] (candidates:password_set) changed (catalog, checks); previous review of candidates:password_set (accepted) no longer applies
exit 4 (fingerprint_changed)
```

Named `_reset_link_ok`, the helper gives the same two lines and exit 4.

### Acceptance criteria

- [ ] Both snippets exit 0: a same-module helper called with plain names is normalised like the other extracted helpers (see "Fingerprints" in docs/CONCEPTS.md), whether its name looks like a check or it only returns the result of a recognised check.
- [ ] A helper that changes the result (`return True`, `or`, a swallowed exception) still raises a finding. Tests for both directions.
